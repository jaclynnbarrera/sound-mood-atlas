Sound Mood Atlas — Engineering Notes for Agents

This document captures project-specific build, configuration, and testing knowledge to accelerate future work. It assumes an experienced Node/React developer.

Backend (Node/Express)
- Location: backend/
- Entrypoint: src/server.js (Express 5)
- Port: 3000 (configurable via PORT)
- Static assets: backend/public served at /
- API:
  - GET /api/health → { status: "ok" }
  - GET /api/songs → JSON array (generated by build:data). If missing or invalid, API returns 500 with guidance.

Data build pipeline
- Script: npm run build:data → node scripts/buildChartData.js
- Input: backend/data/dataset.csv
- Output: backend/data/songs.json (consumed by /api/songs)
- Assumed CSV columns (Spotify-style):
  - track_name, artists, track_genre, valence, energy, tempo, danceability, popularity
- Transform details:
  - Parses CSV, coerces numerics, drops rows missing track_name or artist
  - Sorts by popularity desc, slices top 200 (SONG_LIMIT)
  - Writes pretty-printed JSON

Postgres ingestion (optional, not used by server.js)
- Script: backend/scripts/ingest.js (requires DATABASE_URL in .env)
- Behavior: Reads the same CSV and INSERTs into a songs table; wraps in a transaction and logs every 1k inserts.

Typical Backend Workflow
1) Ensure dependencies are installed (node_modules already present in repo snapshot):
   - cd backend
   - npm install
2) Generate data (required for /api/songs):
   - Place dataset.csv under backend/data/
   - npm run build:data
3) Run the API server:
   - npm start
   - Visit http://localhost:3000/api/health and /api/songs

Frontend (Vite + React)
- Location: frontend/
- Dev server: Vite on http://localhost:5173
- Proxy: vite.config.js proxies /api → http://localhost:3000, so backend must run on 3000 in dev.
- Scripts:
  - npm run dev → start Vite dev server
  - npm run build → production build
  - npm run preview → preview built assets
- No test runner is configured for the frontend at present.

Testing Guidance (Project-specific)
- No dedicated test framework is configured in backend or frontend. For quick API checks without adding deps, use small Node scripts with assert.
- Example health-check test (used to validate the flow during authoring of this note):
  - Precondition: backend server running on :3000
  - One-off script (not kept in repo): backend/scripts/health.temp.test.js
    - Performs HTTP GET /api/health, asserts 200 and {status:"ok"}
    - Run: node backend/scripts/health.temp.test.js
    - Output on success: "OK health.temp.test: passed"
  - This file was created, executed successfully, and then removed to keep the repo clean.
- Recommendation: If sustained testing is desired, adopt one of:
  - Backend: tap or Node’s built-in test runner (node --test) to avoid extra deps; or Jest for richer tooling.
  - Frontend: Vitest integrates seamlessly with Vite.

Adding Proper Tests Later (suggested layout)
- Backend with node --test:
  - Add to backend/package.json: { "scripts": { "test": "node --test" } }
  - Place tests under backend/test/*.test.js using node:test and assert
- Frontend with Vitest:
  - npm i -D vitest @testing-library/react @testing-library/user-event jsdom
  - Add to frontend/package.json: { "scripts": { "test": "vitest" } }
  - Configure test environment: define test in vite config or vitest.config.ts with environment: "jsdom"

Operational/Debug Notes
- /api/songs failure mode:
  - If songs.json is missing or invalid, server responds 500 with a helpful error. Run npm run build:data after placing dataset.csv.
- Data assumptions: Numeric coercions fall back to 0; popularity sort drives the top 200 selection, which directly shapes the UI dataset.
- Ports: Frontend assumes backend on 3000 due to Vite proxy; keep them aligned or adjust proxy.
- Env: .env only needed for Postgres ingest (DATABASE_URL). The running server does not currently require env.

Code Style & Conventions
- Backend: CommonJS modules, minimal comments, straightforward imperative scripts. Match existing formatting; avoid introducing ESM in backend without a coordinated change.
- Frontend: ESM, React 19, Vite. Follow existing import order and functional components pattern.
